# Pipeline Options & Execution Reference Manual

This manual serves as a quick-reference guide for running, configuring, and analyzing both pipelines in the **Predictive Semantic Cache Invalidation** project.

---

## 1. System Setup & Environment

Before executing any pipeline, ensure your environment is set up.

### 1.1 Python Virtual Environment
Install all dependencies (including the patched `cpgqls-client` version):
```powershell
# Activate your venv
.\venv\Scripts\Activate.ps1

# Install requirements
pip install -r requirements.txt
```

### 1.2 Joern Query Server
If running in any Joern parser mode (`joern_hybrid` or `joern_only`), the query server **must** be active in a separate terminal:
```powershell
# 1. Temporarily add Joern to PATH in the new shell (if not done permanently)
$env:PATH += ";C:\joern-cli-windows\joern-cli"

# 2. Start the Joern query server on default port 8080
cd C:\joern-cli-windows\joern-cli
.\joern.bat --server
```

## 2. Pipeline 1: Model Training & Selective Re-Embedding (`run_experiment.py`)

This pipeline processes repository commits, builds CPG/topological features, trains the Drift Predictor (Random Forest), and runs selective re-embedding.

### 2.1 CLI Option Reference

| Argument | Type / Options | Default | Description |
| :--- | :--- | :--- | :--- |
| `--repo-url` | String (Git URL or Local Path) | `https://github.com/psf/black.git` | Target repository to clone/analyze. |
| `--model-name` | String | `sentence-transformers/all-MiniLM-L6-v2` | Hugging Face model for extracting code embeddings. |
| `--parser-mode` | `ast` \| `joern_hybrid` \| `joern_only` | `ast` | How the repository is parsed and CPG/AST is generated. |
| `--num-commits` | Integer | `50` | Total number of commit snapshots to extract from history. |
| `--commit-stride` | Integer | `20` | How many commits to skip between sampled snapshots. |
| `--threshold` | Float | `0.02` | Drift distance limit above which a node is marked "stale". |
| `--threshold-mode`| `fixed` \| `dynamic` | `dynamic` | Whether threshold is static or dynamically computed. |
| `--clean-mode` | Flag | `False` (Disabled) | Strips all comments and docstrings before embedding. |
| `--context-chunking`| Flag | `False` (Disabled) | Appends callers/callees signature stubs to code context. |
| `--config` | String | `None` | Path to a JSON configuration file (overrides defaults). |
| `--subset` | Integer | `None` | Restricts commit processing count (useful for dry runs). |

### 2.2 Example Execution Commands

#### A. Run in AST Mode (No Joern Server Required - Python Only)
```powershell
./venv/Scripts/python.exe run_experiment.py --parser-mode ast --num-commits 15 --model-name "sentence-transformers/all-MiniLM-L6-v2"
```

#### B. Run in Joern Hybrid Mode (Uses Joern Server + AST Local Fallbacks)
```powershell
./venv/Scripts/python.exe run_experiment.py --parser-mode joern_hybrid --num-commits 15 --model-name "microsoft/codebert-base"
```

#### C. Run on a Local Repository with Jina Code Model
```powershell
./venv/Scripts/python.exe run_experiment.py --repo-url "C:\projects\my-project" --model-name "jinaai/jina-embeddings-v2-base-code" --parser-mode joern_hybrid --num-commits 10
```

## 3. Pipeline 2: Search Retrieval Quality Benchmarking (`benchmark_runner.py`)

This pipeline runs search queries against the selective vector index (built via Pipeline 1) and compares search ranking degradation against a ground-truth baseline re-index.

### 3.1 CLI Option Reference

| Argument | Type / Options | Default | Description |
| :--- | :--- | :--- | :--- |
| `--repo-path` | String | `workspace/black` | Path to the local git clone. |
| `--strategies` | Comma-separated strings | `changed_only,fixed_hop,predictive_ml,full_reindex` | List of invalidation strategies to compare. |
| `--query-mode` | `synthetic` \| `curated` \| `hybrid` | `synthetic` | Search query sources. |
| `--predictions-path`| String | `predictions.json` | Path to predictions generated by Pipeline 1. |
| `--output-dir` | String | `benchmark_runs` | Folder where benchmark metrics are saved. |
| `--num-commits` | Integer | `5` | Number of commit snapshots to evaluate. |

### 3.2 Example Execution Commands

#### A. Compare Default Strategies Side-by-Side
```powershell
./venv/Scripts/python.exe benchmark_runner.py --repo-path workspace/black --strategies changed_only,fixed_hop,weighted_bfs_decay,predictive_ml,full_reindex --num-commits 5
```

## 4. Invalidation Strategies Cheat Sheet

When comparing cache invalidations, you can evaluate the following **6 strategies**:

1.  **`full_reindex`:** Re-embeds 100% of the codebase at every commit. Represents perfect quality (Recall = 1.0) but maximum possible cost.
2.  **`changed_only`:** Re-embeds *only* the functions modified directly in the Git commit. Very low cost, but degraded search quality.
3.  **`fixed_hop_k1` / `fixed_hop_k2`:** Re-embeds modified functions + immediate neighbors within 1 or 2 hops in the call graph.
4.  **`baseline_d_pagerank_propagation`:** Re-embeds the top 30% most central/influential nodes in the call graph (ranked by PageRank).
5.  **`weighted_bfs_decay`:** Propagates outward along caller edges, decaying strength by connection coupling. Stops when strength decays below `0.05`.
6.  **`predictive_ml` (Proposed):** Uses our trained Random Forest model to predict exact drift probabilities, updating only those above the threshold.

## 5. Directory Outputs Reference

### 5.1 Pipeline 1 Results (`results/results_<model>_<mode>_commits<count>_<stride>/`)
*   `results.json`: Aggregated model training and test performance.
*   `summary_report.txt`: Human-readable summary report with top feature importances and strategy averages.
*   `drift_predictor.pkl`: Trained Random Forest model file.
*   `*.png`: Evaluation graphs (Pareto frontier, confusion matrix, feature importance, ranking metrics).
*   **`commit_logs/` (Subdirectory):**
    Contains a JSON log for *each* commit pair (`commit_from_<hash>_to_<hash>.json`) storing:
    *   `git_changes`: Added, modified (semantic only), and removed entities.
    *   `dependency_graph`: Call graph nodes and edges.
    *   `features_matrix`: Matrix of 25 features calculated for all entities.
    *   `cosine_drifts`: Raw actual embedding drift values.
    *   `invalidation_decisions`: ML predictions and stale/fresh decisions.
    *   `strategy_re_embeddings`: Exact lists of entities re-embedded under all strategies.

### 5.2 Pipeline 2 Results (`benchmark_runs/<run_id>/`)
*   `benchmark_config.json`: The runtime configuration parameters.
*   `per_query_results.jsonl`: Detail records for each query containing baseline rank, selective rank, scores, and deltas.
*   `summary_metrics.json`: High-level metrics for the run.
*   `summary_report.md`: Detailed markdown report with performance tables.
